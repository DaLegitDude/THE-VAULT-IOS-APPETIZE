# Vault for iPhone — setup guide

This project now has an `ios/` folder alongside `android/`, generated by
Capacitor, plus a Swift plugin (`ios/App/App/VaultLocalFilesPlugin.swift`)
that gives the app the same "pick a local music folder and remember it"
behavior as the Android build, using iOS's own document-picker APIs instead
of Android's Storage Access Framework.

Push this to GitHub like you already do for the Android build, and
`.github/workflows/build-ios.yml` will compile it automatically on GitHub's
own Mac servers. There are three tiers:

**Tier 1 — compiles automatically, no setup needed.** Every push builds the
app for the iOS Simulator and uploads it as the `vault-ios-simulator-app`
artifact. This just proves the code compiles; you can't install a Simulator
build on a real iPhone (it's a completely different binary format, not
just an unsigned version of the same file), but it's a free, instant sanity
check with nothing to configure -- and see "Trying it without a phone at
all" below for how to actually run this build in a browser.

**Tier 2 — free, real install, no Apple Developer Program.** Every push
also produces an *unsigned* .ipa (the `build-unsigned-ipa` job) that you
sign yourself with a free Apple ID using a tool like Sideloadly, entirely
from your PC. No $99/year, no Mac required on your end. Trade-off: the
install expires after 7 days unless you re-sign it, and a free Apple ID can
only have 3 sideloaded apps active at once. See "Free install via
Sideloadly" below.

**Tier 3 — a real signed .ipa via a paid account.** Needs an Apple
Developer Program membership ($99/year) and some one-time setup, but gets
you around the 7-day/3-app limits and unlocks TestFlight for sharing with
the whole Discord community without everyone needing their own Sideloadly
setup.

## Trying it without a phone at all (Appetize.io)

There's no real "iOS emulator" for Windows/Linux the way there is for
Android -- most things marketed that way (iPadian, random "best iOS
emulator 2026" GitHub repos, etc.) either don't actually run real app
binaries or are outright unsafe to download. Apple's own Simulator only
runs on a Mac, as part of Xcode.

The one legitimate exception is [Appetize.io](https://appetize.io/), a
real company that streams an actual iOS Simulator instance to your browser
from their cloud. It's genuinely free for light use: **100 minutes/month,
capped at 3 minutes per session** -- plenty to confirm Vault looks and
plays right without touching a phone at all.

1. Push to GitHub, let `build-ios.yml` finish, then download the
   `vault-ios-simulator-app` artifact from the run -- that's
   `Vault-simulator.zip`, already in the zip format Appetize wants (it's a
   zipped `App.app`, not the `.ipa` files from the other two jobs -- those
   won't work here, Appetize only runs Simulator builds).
2. Go to [appetize.io/upload](https://appetize.io/upload), sign up free,
   and drag `Vault-simulator.zip` in.
3. It'll boot into a virtual iPhone screen right in your browser within a
   few seconds -- click around like it's a real phone.

It's a real compiled build of Vault (same Swift folder-picker plugin and
all), so the actual iOS document picker will open when you tap "Select
music folder" -- but Appetize's virtual device is a fresh, empty cloud
instance with no music library of your own already on it, so there's
nothing to actually pick and play. Treat this as a way to check the UI,
layout, and navigation look right, not a full functional test.

## Tier 2: free install via Sideloadly (no Developer Program)

1. Push to GitHub, let `build-ios.yml` run, then open the workflow run and
   download the `vault-ios-unsigned-ipa` artifact — that's `VaultUnsigned.ipa`.
2. Install [Sideloadly](https://sideloadly.io/) on your Windows PC (a
   Mac-only alternative is AltStore, see below).
3. Plug your iPhone in over USB. On the iPhone: Settings → Privacy &
   Security → scroll down and enable **Developer Mode** (iOS 16+; the phone
   will ask to restart).
4. In Sideloadly, drag `VaultUnsigned.ipa` in, sign in with your regular
   (free) Apple ID when prompted, and hit Start. Sideloadly re-signs the
   app on the fly and pushes it to the phone.
5. On the phone, the first launch will be blocked by iOS as "Untrusted
   Developer" — go to Settings → General → VPN & Device Management, tap
   your Apple ID under Developer App, and tap Trust.

**The 7-day catch:** free-tier signatures expire after a week, at which
point Vault just stops opening until you redo step 4 (Sideloadly remembers
your settings, so it's quick). If you'd rather not replug weekly,
[AltStore](https://altstore.io/) uses the same free-Apple-ID mechanism but
its companion app (AltServer) can auto-refresh the signature over WiFi
before it expires — worth switching to if this becomes your main
distribution method. Either way, a free account also caps you at 3
sideloaded apps installed at once, so this works well for yourself or a
couple testers but doesn't scale to the whole Discord server without
everyone doing their own Sideloadly/AltStore setup, or you moving to Tier 3.

## Tier 3: one-time Apple setup (paid Developer Program)

1. **Enroll in the Apple Developer Program** at
   [developer.apple.com/programs](https://developer.apple.com/programs) —
   $99/year, tied to your Apple ID.
2. **Create a Distribution certificate.** In Xcode (Settings → Accounts →
   your Apple ID → Manage Certificates → +) or via
   [developer.apple.com/account/resources/certificates](https://developer.apple.com/account/resources/certificates).
   Export it as a `.p12` file with a password — Keychain Access on a Mac:
   right-click the certificate → Export.
3. **Register your devices** (for ad-hoc distribution to Discord members'
   phones) at Certificates, Identifiers & Profiles → Devices, using each
   phone's UDID. TestFlight distribution skips this step but needs an extra
   App Store Connect upload step this workflow doesn't do yet — ask me if
   you want that added later.
4. **Create an App ID** matching `fun.thevaulthub.vault.mobile` under
   Identifiers, then a **Provisioning Profile** (ad-hoc or development type)
   that ties together your App ID, your Distribution certificate, and your
   registered devices. Download the `.mobileprovision` file.
5. **Find your Team ID** — it's shown on the Membership page of your
   developer account.

## Wiring it into GitHub Actions

In your repo: Settings → Secrets and variables → Actions → New repository
secret. Add these:

| Secret name | Value |
|---|---|
| `IOS_DIST_CERTIFICATE_BASE64` | `base64 -i YourCert.p12 \| pbcopy` (Mac) or `certutil -encode YourCert.p12 tmp.b64` (Windows), then paste the contents |
| `IOS_DIST_CERTIFICATE_PASSWORD` | the password you set exporting the `.p12` |
| `IOS_PROVISION_PROFILE_BASE64` | same base64 trick on your `.mobileprovision` file |
| `IOS_TEAM_ID` | your Team ID from step 5 |
| `IOS_KEYCHAIN_PASSWORD` | any random password — only used transiently inside the CI run |

Once all of these exist, the `build-signed` job in `build-ios.yml` stops
skipping and produces a real signed `.ipa`, downloadable from the Actions
run's "Artifacts" section.

## Installing the .ipa on a phone

For ad-hoc builds (devices you registered in step 3), the simplest path is
[Apple Configurator](https://apps.apple.com/us/app/apple-configurator/id1037126344)
on a Mac, or a service like Diawi — drag the `.ipa` in, get an install link.
TestFlight is nicer for a community (no UDID registration, easy updates,
90-day builds) but needs an App Store Connect upload step layered on top of
this workflow — let me know if you want that built out next.

## What's different from the Android build

- `VaultLocalFilesPlugin.swift` replaces `VaultLocalFilesPlugin.java` —
  same four methods (`pickFolder`, `getSavedFolder`, `listChildren`,
  `readFile` with the bounded `maxBytes` perf fix), same JS-facing shape,
  so none of `www/local-library.js`, `app.js`, or `index.html` needed to
  change at all.
- Folder access uses `UIDocumentPickerViewController` + a security-scoped
  bookmark (iOS's equivalent of Android's persisted SAF grant) instead of
  Android's tree URI.
- `PrivacyInfo.xcprivacy` declares the app's UserDefaults usage, required
  for App Store submission since iOS 17.
- Discord Rich Presence is a desktop-only feature already (Discord's Game
  SDK doesn't run on mobile), so there's nothing iOS-specific needed there.
